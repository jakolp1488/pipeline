# App Review / Audit — что требует TikTok для публичного постинга

Форма подачи: **https://developers.tiktok.com/application/content-posting-api**
(из страницы приложения: Products → Content Posting API → Apply for audit).

## Что TikTok проверяет

1. **Работающий сценарий с явным согласием пользователя.** Пользователь сам инициирует
   каждый пост, сам видит превью/данные поста перед публикацией и может отменить.
2. **Соблюдение UX-гайдлайнов экспорта (Content Sharing Guidelines):**
   - перед публикацией вызывается `creator_info/query` и интерфейс показывает
     фактический аккаунт (аватар, @username);
   - пользователь выбирает privacy level **из тех опций, что вернул API**
     (хардкод или скрытие опций = отказ);
   - настройки duet/stitch/comment показываются и отправляются согласно выбору;
   - запрещена авто-публикация без действия пользователя в момент отправки.
3. **Соответствие сайту и документам:** сайт приложения доступен, описание на сайте
   совпадает с тем, что делает приложение; privacy policy реально описывает TikTok
   OAuth, токены, что хранится и как удаляется; terms существуют и доступны.
4. **Минимальные права:** приложение запросило только `user.info.basic` + `video.publish`,
   а не всё подряд.
5. **Безопасность токенов:** секрет клиента не светится во фронтенде (мы — Cloudflare
   Worker + KV, во фронтенде только ссылка авторизации).
6. **Нет автоматического спама:** нет multi-post, кросспоста, массового постинга;
   дневные лимиты TikTok не обходятся.

## Что показать на demo-видео (2–4 минуты, экран + голос или субтитры)

1. Открыть `https://jakolp1488.github.io/pipeline/` — показать описание и ссылки на
   privacy/terms.
2. Нажать **Connect TikTok** → страница авторизации TikTok → consent screen
   (показать, какие scope запрашиваются) → «TikTok connected».
3. В приложении выбрать готовое видео → показать экран перед публикацией: превью,
   поле caption, **выпадающий список privacy level, заполненный из creator_info**,
   тумблеры duet/stitch/comment → подтвердить.
4. Показать статус обработки → открыть TikTok → видео появилось (приватный режим,
   объяснить: «unaudited app posts privately by design until audit passes»).
5. Показать отмену: такой же экран → не подтверждать → ничего не опубликовано.
6. Показать отзыв доступа (revoke) — «Disconnect»/удаление из настроек TikTok.

Порядок кадров важнее красоты: ревьювер должен за 2 минуты увидеть
**consent → выбор privacy из API → явное подтверждение → результат → revoke**.

## Требования к сайту / privacy / terms (чек-лист, который они смотрят)

Сайт:
- название и назначение совпадают с приложением;
- контакты (email) видны;
- ссылки privacy + terms кликабельны и не 404;
- упоминание, что приложение не является частью TikTok и не спонсируется TikTok
  (є в terms, раздел 4).

Privacy Policy:
- описание OAuth и конкретных scopes;
- где и как долго хранятся access/refresh токены;
- публикация видео = передача файла TikTok;
- удаление данных / отзыв доступа;
- third parties (TikTok, Cloudflare, GitHub);
- «не продаём данные».

Terms:
- ответственность пользователя за контент и права на него;
- запрет спама и обхода лимитов;
- «AS IS», лимит ответственности;
- прекращение/отключение.

## UX Direct Post — красные флаги, из-за которых отказывают

- privacy level захардкожен или всегда PUBLIC_TO_EVERYONE без выбора пользователя;
- публикация «в одну кнопку» без экрана подтверждения;
- показ аккаунта, отличного от creator_info (или без показа);
- авто-ретраи постов после spam-ошибок;
- запрос лишних scope (video.list, stats и т.п. «на будущее»).

## После одобрения

- снимается `unaudited_client_can_only_post_to_private_accounts`;
- можно публиковать PUBLIC_TO_EVERYONE и т.д. по выбору пользователя;
- любые изменения сценария (новые scope, новый UX) — повторная подача.
